## Review focus

다음 측면에 집중 review 요청:

### 1. HC consistency (절대 규칙 무결성)
- §14 Fleet Mode 규칙이 HC-1~10 중 어느 것이라도 약화·우회·재정의하는가?
- 특히 HC-10 (Local-Extends-Only) 위반 없는가 — Fleet F3 capability manifest freeze + F9는 HC-10 강화 방향이어야 함
- HC-7/8/9 (secret / external / destructive)는 child에서도 그대로 적용되는가?

### 2. Fleet 9 rules의 silent gap
- F1 (interface lock at split) — child가 escalate해야 하는 *정확한 위치* 명세 충분한가? (현재 SUBTREE-PROMPT는 escalation.md 언급, 의무화는 X)
- F2 (횡단 invariant 식별 의무) — Blueprint Phase 01 Exit에 이 의무가 *명시*되어 있는가? (현재 §14에만 명시, phases/01-blueprint.md 변경 안 함 — gap 가능성)
- F4 (file ownership) — shared 파일 *읽기*까지 막아야 하는가, 쓰기만? 본 review는 쓰기만 막음
- F5 (depth ≤ 2) — child가 본인 phase 02에서 또 split 결정할 때 depth 카운트는 어디서 추적? (현재 SUBTREE-STATUS의 depth 필드만)
- F6 (사용자 승인 게이트) — autonomous 모드에서도 의무. 자동화 우회 risk 없는가?
- F7 (codex review 분배) — child 3 + parent 1 + cross-cutting integration 1 = 비용 폭증 risk. fleet-mini는 self-test 대체했는데, *언제* self-test 대체 가능한가 명문화 없음 (본 dogfood F70-fleet-3로 식별)

### 3. Recursion safety (depth=2 케이스)
- child가 자기 scope에서 또 split → grandchild의 *parent*는 child인데, grandchild의 *root coordinator*는 누구? capability manifest는 *root* freeze인가 *child* freeze인가? §14 명시 부족 가능

### 4. Phase 02 amend의 의무성

## Review format

REVIEW 양식 (`templates/REVIEW.template.md` 참조):
- finding별 `severity` (blocker / major / minor / nit / info)
- `위치` (파일:라인)
- `근거`
- `제안`

특히:
- **blocker / major** finding은 v1.1 ship 전 의무 처리
- **minor / nit / info**는 carry-over OK (v1.2 후보 등록)
- HC-7/8/9 위반 가능성 보이면 자동 blocker

## Out of scope

- 본 review는 *하니스 자체* 변경에 대한 것. fleet-mini의 *계산 로직 정확성* (add/mul/stat의 수학적 correctness)은 review 대상 아님 (이미 32 jest test로 검증).
- 향후 v1.2 amendment 후보 (F70-fleet-1~3)는 *언급*만, 본 review의 finding으로 발행 안 해도 됨.
