## Review focus

### 1. AST lock rule 강도 (F102 v1.3 patch가 진짜 작동하는가)

- `no-restricted-imports` ESLint rule이 *실제로* lock을 enforce하는가?
- alias (`import { x as y }`) catch? — ESLint normalizes할 것
- namespace import (`import * as X`) — gen_eslint_lock.py가 `importNamePattern` 사용 안 함; 이건 v1.4 후보로 명시했지만 *현 v1.3에서 우회 가능*
- re-export barrel (`export { x } from '../auth/index.js'`)는 catch 못함 — v1.4 후보
- multi-line import는 parse_runtime_allowlist 정규식이 잡는가?

### 2. Helper scripts의 production-readiness

- `gen_stub.py`: 함수 시그니처가 generic 또는 overload일 때 정규식이 깨질 가능성
- `gen_ambient.py`: import 제거 후 ambient 안에 type 의존성이 *남아있는* 경우 (Result type 등 import 했던 것 — 본 ambient는 type 의존성 누락)
- `topo_sort.py`: dependency graph가 `a -> b -> c` 같은 체인일 때 정확? `a -> b`와 `c -> a`만 처리 안 함 (parent_path 가능성)
- `gen_eslint_lock.py`: provider가 *없는 export* (re-export only) 일 때

### 3. spawn-subtree-prompts skill과 새 scripts 통합

- v1.2의 spawn skill은 Step 3.5에 per-child tsconfig/jest config 생성을 명시. v1.3은 *추가로* ESLint config 생성도 해야 하는데 — spawn skill에 명시되어 있는가?
- 본 v1.3 amend는 ADR-012에서 *lock-eslint-gen skill 신설* 했지만, *spawn skill의 어느 step*에서 호출되는지 unclear
- 사용자가 v1.3 시작하면 spawn 시 ESLint config 자동 생성되는가?

### 4. ESLint dependency 정책

- v1.3은 ESLint v9+를 *primary enforcement*로 만듬 — 신규 프로젝트 `new-project.sh`가 ESLint를 default install하는가?
- 아니면 사용자가 수동으로 `npm install -D eslint @typescript-eslint/parser`?
- starpin-fleet은 검증 위해 *사후 npm install*했음 (본 dogfood evidence)

### 5. Codex 대체 heuristic 4 조건의 정밀도

- (i) `examples/` or `dogfood/` 경로 — *intent*가 명시될 뿐 path만으론 부족 가능 (real production code가 examples/에 있을 수 있음)
- (ii) LOC < 1500 — Phase 02 단계에 정확한 LOC 측정 어려움 (estimate일 뿐)
- (iii) HC-7/8/9 없음 — Blueprint에서 명시 의무. 그런데 *모르고* 누락한 HC 영향이 있을 가능성
- (iv) 외부 통신/DB write/auth/결제 부재 — *partial* 인 경우 (예: read-only DB)? 명확화 필요

### 6. mid-work escalation 5 카테고리의 sufficient

- (1) lock vs invariant 모순
- (2) shared change required
- (3) 신규 횡단 invariant
- (4) HC 위반 risk
- (5) inter-lock mismatch

5개 외 발견 case 있는가? (예: external dependency 변경 필요 / 성능 budget 부족 / test infrastructure 미흡)

### 7. esm-jest-pattern seed의 활용 경로

- seed는 *읽기 자료*. 신규 프로젝트가 *어떻게 자동 적용*?

- 또는 *모든 TS ESM 프로젝트 default*?
