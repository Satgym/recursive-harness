# Hara v1.9 / starpin v0.10 Review

## Summary

HC-12 is the right response to the post-mortem: unit tests + codex review did not validate the composed first-user flow, and the new Playwright smoke is exactly the kind of gate that would have exposed the login breakage. The main issue is that the current hook does not enforce HC-12 as broadly as HARNESS.md states. As written, `UI surface가 있는 프로젝트` overpromises coverage; the hook only catches tracked `public/` or `frontend/` paths, and `note(...)` dogfood ships remain exempt.

## Findings

### Finding 1: HC-12 enforcement is narrower than the hard constraint wording
- **severity**: blocker
- **target**: [HARNESS.md](/Users/satgym/work/harness/HARNESS.md:32), [.githooks/pre-push](/Users/satgym/work/harness/.githooks/pre-push:26), [.githooks/pre-push](/Users/satgym/work/harness/.githooks/pre-push:140)
- **detail**: HC-12 says every project with a UI surface requires first-flow evidence, but the hook only triggers for `code|harness(...)` ship commits and only detects tracked paths named `public` or `frontend`. It misses common web layouts like `web/`, `client/`, `app/`, `src/pages`, native `ios/`/`android/`, and the current starpin dogfood path because `examples/` is gitignored and shipped through `note(...)`.
- **suggested_action**: Either narrow HC-12 wording to “tracked web UI surfaces detected by hook” or add explicit configuration/marker support, e.g. `.harness/ui-flows.yml` or `.harness/config.toml [ui_smoke]`, with `surface_paths`, `runs_dir`, and required flow slugs. For `note(starpin-v...)`, either infer `examples/starpin/.harness/runs` when present or require a tracked evidence pointer in the harness repo.
- **references**: A.1, A.2, D.4, D.5, E.2
- **capability_candidate**: yes — `candidate_name: ui-flow-smoke-template`, `kind: template field`, `scope: base harness HC-12 enforcement`

### Finding 2: Evidence validation can be satisfied by unrelated or hand-written JSON
- **severity**: major
- **target**: [.githooks/pre-push](/Users/satgym/work/harness/.githooks/pre-push:156), [run-e2e-smoke.sh](/Users/satgym/work/harness/examples/starpin/scripts/run-e2e-smoke.sh:4)
- **detail**: The hook checks only mtime `<24h` plus `"status": "pass"`. It does not require `test_count > 0`, `exit_code: 0`, matching slug, existing Playwright report, current commit SHA, or test names. This is enough for accidental false evidence, and it does not materially prevent fabrication.
- **suggested_action**: Parse JSON and require `status=pass`, `exit_code=0`, `test_count>=1`, `ran_at` within TTL, `report_path` exists, and a configured `slug`/test name. Have the wrapper emit `git_sha`, `command`, and `tests: [...]`; the hook should reject evidence for another commit unless explicitly allowed.
- **references**: A.3, B.3, D.2
- **capability_candidate**: no — concrete enforcement hardening

### Finding 3: Mock OAuth construction gate is insufficient for production safety
- **severity**: major
- **target**: [server.ts](/Users/satgym/work/harness/examples/starpin/backend/src/server.ts:100), [dev-oauth-stub.ts](/Users/satgym/work/harness/examples/starpin/backend/public/lib/dev-oauth-stub.ts:9)
- **detail**: The stub comment says it is gated by `NODE_ENV !== 'production'`, but server wiring still constructs `MockOAuthProvider` in `NODE_ENV=production` when provider env is absent or the Google production flag is unset. If a real deployment misses one provider config, the browser-visible stub can mint a dev session for that provider. The construction gate is not enough.
- **suggested_action**: Add an explicit mock gate such as `STARPIN_ENABLE_MOCK_OAUTH=true`, refuse Mock providers in real `NODE_ENV=production`, and use a separate `STARPIN_PROD_SIM_ALLOW_MOCK_OAUTH=true` for local prod-sim. Also block serving `/dev-oauth-stub.html` unless that gate is enabled.
- **references**: C.5
- **capability_candidate**: no — starpin auth hardening

### Finding 4: Smoke wrapper ignores `STARPIN_E2E_PORT` for health check
- **severity**: minor
- **target**: [run-e2e-smoke.sh](/Users/satgym/work/harness/examples/starpin/scripts/run-e2e-smoke.sh:35), [playwright.config.ts](/Users/satgym/work/harness/examples/starpin/backend/playwright.config.ts:11)
- **detail**: Playwright uses `STARPIN_E2E_PORT`, but the wrapper health check always probes `localhost:3000`. A custom-port smoke can fail before Playwright or, worse, verify the wrong process.
- **suggested_action**: Define `PORT="${STARPIN_E2E_PORT:-3000}"` once and use it for both health output and curl.
- **references**: B.4
- **capability_candidate**: no — local script consistency fix

### Finding 5: Console 404 filter is too broad
- **severity**: minor
- **target**: [login-smoke.spec.ts](/Users/satgym/work/harness/examples/starpin/backend/tests/e2e/login-smoke.spec.ts:25)
- **detail**: Ignoring every `Failed to load resource (Not Found)` can hide product bugs such as a missing JS chunk, CSS, image atlas, or API-backed static resource. For a smoke gate, broad suppression weakens the signal.
- **suggested_action**: Fail on `response.status() >= 400` for same-origin resources except an explicit allowlist like `/favicon.ico`, `/robots.txt`, and maybe source maps in dev.
- **references**: B.5
- **capability_candidate**: no — test hygiene fix

### Finding 6: HC-12 scope limit should be explicit
- **severity**: minor
- **target**: [HARNESS.md](/Users/satgym/work/harness/HARNESS.md:32), [DECISIONS.md](/Users/satgym/work/harness/DECISIONS.md:54)
- **detail**: The current wording can be read as broad UI quality coverage. The actual gate is first happy-path composition only; it does not cover performance, security, data loss, cross-browser, or all user flows.
- **suggested_action**: Add one sentence: “HC-12 is first-flow happy-path composition evidence only; broader flow matrix, performance, a11y, security, and destructive/data-loss checks remain separate gates.”
- **references**: B.1, B.2, E.3
- **capability_candidate**: no — wording calibration

### Finding 7: Version labels still say v1.8
- **severity**: nit
- **target**: [HARNESS.md](/Users/satgym/work/harness/HARNESS.md:1), [.githooks/README.md](/Users/satgym/work/harness/.githooks/README.md:1), [.githooks/pre-push](/Users/satgym/work/harness/.githooks/pre-push:2)

- **suggested_action**: Bump these labels to v1.9 or make them version-neutral.
- **references**: D.1
- **capability_candidate**: no — doc drift
