### Finding 2
severity: blocker  
위치: [scripts/ui-visual-review.sh](/Users/satgym/work/harness/scripts/ui-visual-review.sh:96)  
근거: body fallback이 strict하지 않습니다. bool은 `(true|false)\b`, int는 `(\d+)\b`라서 `codex_pass: true. HC-13...`, `codex_pass: true, ...`, `major_count: 1 finding remains`를 각각 `true`, `true`, `1`로 받아들입니다. 이는 ADR-030의 “long narrative trailing 거부”와 prompt의 “body narrative verdict line rejected”를 정면으로 위반합니다. Empty front-matter 뒤 body narrative도 같은 이유로 pass됩니다.  
제안: body fallback은 line-end anchoring을 걸어야 합니다. 예: bool `^\s*key\s*:\s*(true|false)\s*$`, int `^\s*key\s*:\s*(\d+)\s*$`. Inline comment 허용은 front-matter parser에서만 처리하는 편이 안전합니다.

B: `codex-exec-review.sh`의 direct `DEST` suffix는 backward compatible합니다. `REVIEW_ROUND` empty면 기존 파일명 유지, set이면 `-rN` 보존됩니다. 단 `ui-visual-review.sh` caller의 canonical copy가 overwrite 문제를 계속 갖습니다.

C: prompt 문구는 구체적이지만 현재 postprocess가 Codex YAML을 제거하므로 실효성이 없습니다.

D/E: skill v0.3 promotion, PATTERNS의 subagent recovery/scope chunking, HARNESS chunking note 자체는 evidence 기반이고 문서 길이도 과하지 않습니다.

F: starpin v0.17 evidence JSON schema는 v2.3.1과 incompatible하지 않습니다. 다만 기존 raw `ui-visual-*` generated files는 canonical fields가 없어 새 parser로 pass하지 않는 사례가 있고, 이게 바로 postprocess/runner 연결 문제를 보여줍니다.
