**Review Notes**

§deliverable-categories는 실제 누락 패턴을 잘 덮습니다. Code / Styling / Tests / Fixture / impl-review의 split은 v0.16~v0.17.3 누락과 대응되고, ARIA는 profile-stars v0.17.2 사례와 직접 연결됩니다. z-index도 starpin 현재 CSS의 modal 1000, detail overlay 1010, banner 950, FAB 50과 맞습니다. 다만 profile dropdown 999 같은 기존 값은 convention의 범위 밖이라 “core overlay convention” 정도로 읽는 게 정확합니다.

§modal-overlay-race는 anti-pattern과 corrected pattern 차이가 명확합니다. `_removeOverlayDom()`과 public close의 분리는 sky-detail-page 현재 구현과도 일치합니다. 감지 방법은 충분히 debuggable하지만, “hashchange 2회 연속”은 vanilla hash router에서 특히 강한 신호이고 React/Vue router에서는 `navigate()`/`router.push()`/state transition 로그로 일반화해 적는 편이 더 재사용성이 좋습니다.

Cross-impact는 적절합니다. §subagent-recovery는 실패 후 진단/회복이고, §deliverable-categories는 실패 전 prompt prevention이라 중복보다 보완 관계입니다. §scope-chunking 표는 ship size 판정, 5-category 표는 책임 completeness 판정이므로 row가 동일하지 않습니다. 다만 5-category가 대부분 비어 있으면 “ship이 너무 얇다”는 보조 신호로 쓸 수는 있습니다.

Doc length/dogma 측면도 허용 범위입니다. HARNESS 추가는 1줄이라 trim 원칙 위반은 아니고, 새 HC를 만들지 않고 PATTERNS discipline에 둔 결정도 합리적입니다. PATTERNS는 큰 섹션이 늘었지만 dogfood precedent가 구체적이라 documentation theater로 보이진 않습니다.

Regression sweep은 정적 기준으로 확인했습니다. news-modal, profile-stars, messaging-full, permission-ui는 현재 modal-overlay-race anti-pattern에 해당하지 않습니다. sky-detail-page는 v0.17.3에서 이미 internal DOM cleanup 분리 패턴으로 고쳐져 있습니다. v2.3.2 직후 별도 patch는 필요 없어 보이고, ADR-032의 v0.18 wholesale dogfood validation 계획도 적절합니다.
