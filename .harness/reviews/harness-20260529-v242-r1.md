**Finding 1**

severity: minor  
위치: [scripts/ui-visual-review.sh](/Users/satgym/work/harness/scripts/ui-visual-review.sh:195)  
근거: retry loop가 `1 2 3 4 5` 각 attempt 뒤에 무조건 `sleep 1` 합니다. 그래서 실제 probe 시점은 대략 `t=0,1,2,3,4s`이고, 파일이 `t=4.1~5.0s` 사이에 생기면 마지막 sleep 후 재검사 없이 fail합니다. “5초 안에 detect”라는 ADR/설명과 정확히 일치하지 않습니다.  
제안: 마지막 iteration에서는 sleep하지 않거나, `for _try in 0 1 2 3 4 5` 식으로 6번 probe해서 `t=5s` 재검사를 포함하세요. 정상 path는 현재처럼 첫 성공 시 break라 영향 없습니다.

ARIA grep은 의도에 맞습니다. `\baria[- ]?label\b`는 `aria-label`, `aria label`, `ARIA-LABEL`을 잡고, `aria_label`은 제외합니다. `aria-labelledby`는 실제로 매치되지 않습니다. `label` 뒤의 다음 문자가 `l`이라 word boundary가 성립하지 않습니다. 이 enforcement가 “명시적 `aria-label` imperative”를 요구하는 것이면 `aria-labelledby`만으로 통과시키지 않는 쪽이 더 일관됩니다.

PATTERNS 섹션은 충분히 명확합니다. 한국어 설명과 영어 attribute name 혼용은 이 레포 문체와 맞고, copy-paste snippet에 실제 lint 통과 토큰인 `aria-label`이 포함되어 있습니다. precedent도 v0.17.2 button, v0.19 search input으로 현재 변경의 원인을 잘 대표합니다.

Regression 확인: 임시 prompt로 `aria-label`, `aria label`, `ARIA-LABEL`, comment case는 PASS, `aria_label`과 `aria-labelledby`는 FAIL을 확인했습니다. review-mode prompt는 `--strict`여도 SKIP됩니다.
